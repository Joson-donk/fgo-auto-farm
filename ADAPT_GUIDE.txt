二、机器人如何看与决策（词汇）
--------------------------------------------------------------------------------
界面 = 模板匹配 TM_CCOEFF_NORMED，一般阈值 0.8~0.96（助战名字门槛更高）。
卡色 = HSV 认 B/A/Q；手牌 5 槽固定坐标。
从者归属 = 手牌上方头像 ROI(约 134x151) 匹配 servant 模板；模板必须严格小于 ROI。
波次 = HUD「场次 x/3」模板 wave_1..3.png。
宝具 = 优先选卡视图里的竖卡模板；也可只用号位坐标 + 存在性采样（无模板条目）。
技能 CD = 图标 ROI 灰度对比本局基线（约 基线-25 以下视为 CD）；无基线时用较低全局下限。
         偏暗图标可能假 CD——先复检/调配置，禁止为此改写引擎匹配算法。
技能目标类型:
  None                      自/群，无弹窗
  ("servant", n)            我方 n 号位（1-based，弹窗必点）
  ("servant_if_prompt", n)  有弹窗才点我方 n，无弹窗当自/群
  ("enemy", n)              敌方 n 号位
号位约定: preferred_servant / np servant 字段用 0-based（0=左,1=中,2=右）。
技能键 skill_0..skill_8 对应前排三人各三技能，从左到右。

三、已验证原则
--------------------------------------------------------------------------------
P1 爆发留波: AoE 宝具用 min_wave 留到最终波。
P2 宝具当行动一: 选卡视图先点宝具再凑手牌。
P3 技能必须写清目标类型，禁止盲点己方。
P4 阵亡换人后清空已用技能记录，靠 CD 亮度保护。
P5 败北默认只用令咒续关一次，禁止圣晶石。
P6 AP 不足吃苹果；行序上→下是 圣晶石/金/银/铜(铜常需滚动)。
P7 助战: 点进关卡后才有助战页；默认攻击力从高到低，不要点升/降序。
P8 队伍确认页可用 party_support_*.png 校验立绘，不对就返回重选。
P9 慢=错: 固定长睡改成轮询+早退；点击后等新帧。

四、新副本适配流程
--------------------------------------------------------------------------------
4.1 问完「〇」里的 Q1–Q7，再动手。
4.2 用户停在助战选择页（事件本: 地图点节点 → 点关卡横幅进助战）。
4.3 模板:
    必备 support_<key>.png（助战名字条）

BATTLE_CLASSES["<KEY>"] = {"label": "显示名", "ready": True}
BATTLE_CLASS_PROFILES["<KEY>"] = {
    "support_label": "助战中文名",
    "support_template": "support_xxx.png",
    "party_support_template": "party_support_xxx.png",  # 可选但推荐
    "support_filter": None,  # 或职阶筛选 key；列表默认职阶正确时用 None

    # 可选 np_release_all_ready=True：同回合多个就绪宝具都先放（默认 False 保持旧行为）
    "opening_skills": [("skill_2", None)],  # 可选，进战后优先放的
    "skills": [
        ("skill_0", None),
        ("skill_1", ("servant", 3)),
        # ... 最多 skill_8
    ],
    "check_skills_each_turn": True,
    "skill_reclick": 3,
    "require_servant_recognition": False,
    "np_templates": [
        {"template": "np_card_xxx.png", "servant": 0, "from_turn": 0},
        {"servant": 2, "from_turn": 0, "min_wave": 3},
    ],
    "preferred_servant": 2,
    "prefer_servant_every_turn": True,  # 可选
}

4.5 验证（一步失败就停）:

    # 停在助战页:
    python main.py --class KEY --preview

================================================================================
五、坑位
--------------------------------------------------------------------------------
K1 从者头像模板 ≥ ROI → 整列跳过。裁完打印 shape。
K2 苹果行序不是「常识顺序」，误点会点到圣晶石。
K3 B 卡姿势变 → 单头像模板不够；周回可关 require_servant_recognition。
K4 宝具竖卡只在选卡视图；预览扇形没有。
K5 模板裁错状态 → 误命中。必须自匹配≈1.0，反例<0.6。
K6 活动次数/风暴罐不足要关弹窗并停，不要死循环重开。
K7 cv2/numpy 版本不要混用；用项目 .venv。
K8 助战半截卡贴底/贴顶不要点，先滚动（SUPPORT_NAME_*_MARGIN）。
K9 名字匹配高分仍可能点错人 → 点左侧立绘 + 队伍页立绘校验。
K10 人和脚本不要同时操作；先停干净旧 python 进程再跑。

六、代码规范（给改代码的人 / AI）
--------------------------------------------------------------------------------
C1 配置驱动: 新本逻辑尽量只进 BATTLE_CLASS_PROFILES，不写死在 fgo_bot 分支里。
C2 坐标一律用屏幕比例 (0~1)，禁止写死像素（裁模板除外）。
C3 日志用中文短标签: [助战] [进本] [技能] [宝具] [选卡] [战斗] [结算] [异常]
C4 点击后必须等新帧或短轮询确认状态变化；禁止无依据的 sleep(5)。
C5 技能循环每回合可重检 CD；不要用「本场已用」永久屏蔽（换人除外）。
C6 指向技能: 没弹出目标窗就不要盲点己方从者。
C7 助战点击: 用名字命中点算立绘落点（左偏 + y_offset），保存
   logs/support_match_last.png 与 support_click_last.png 便于核对。
C8 测试: 改 support_select / decision 后跑
   python -m unittest test_support_select test_decision
C9 禁止提交: __pycache__、.venv、logs 大图、*.bak_*、_backup_*、_patch_*、nul
C10 改动前对照用户原话；拿不准就问，不要「先改了再说」。
C11 校准失败时: 重裁模板 / 核对 POS 比例 / 核对职阶筛选；禁止「降低全局阈值碰运气」。
C12 日志里出现假 CD、助战无峰、误开详情时: 先对照第十节字段定位是配置还是时机；
    未经用户点名，不得改亮度公式、助战翻页状态机、选卡打分。

调试图: logs/debug/、logs/support_match_last.png、logs/support_click_last.png

L1 先读标签，再下结论。常用标签:
   [配置] [启动] [进本] [助战] [技能] [宝具] [选卡] [战斗] [结算] [完成]
   [循环] [苹果] [异常] [停止] [保护]


L2 对照字段含义（摘录，含近期标签）:
   - [助战] 本页无匹配 → 向下查找 / 刷新列表
       = 列表已识别，目标名字不在本页（应继续翻页；不是引擎坏了）
   - [助战] 列表尚未加载出卡片（^亮度=…）
       = 仅暗场/过渡；若 det=support 仍长期如此才异常
   - [助战] 选择成功 / 点击后已离开助战列表
       = 助战流程 OK
   - [技能] xxx CD中 (亮度=a < b)
       = 亮度判 CD；开局假 CD 时优先：等动画结束再检、检查该图标是否偏暗、
         配置 check_skills_each_turn；不要先改 CD 公式
   - [技能] 假成功 / 未确认回到技能栏 / 不记已用
       = 点完技能后攻击键未回来或确认窗异常；不应把该 skill 记入已用，
         下回合应还能再试。见硬 CD 门槛与「回到技能栏才记已用」逻辑
   - [技能] 硬CD / 亮度门槛未过
       = 比「假 CD」更暗才认定真 CD；半暗（确认后残留）不要当已放
   - [技能] 目标窗迟到确认 / 检测到从者详情面板
       = 目标点击或模式(servant_target_tap_mode)问题，先核目标号位与模式；
         误开详情应返回，不要改成乱点肖像
   - [进本] 本局要求先选助战，忽略进战误判
       = 连续出击后的正常保护（require_support），不是卡死
   - [苹果] 确认窗 / 双白钮 / 列表页勿点兑换
       = 必须等消耗确认窗（双白钮）出现再点决定；列表同 Y 可能是「兑换树苗」
   - [苹果] 预算用尽 / 停止刷本
       = count 上限到了，属预期停止
   - [保护] 令咒热区拦截
       = 点击落在令咒图标附近被挡，属保护而非漏点

L3 排障顺序（必须按序，前一步能解决就停）:
   1. 确认 class key / 助战模板 / 技能目标配置是否就是用户要的本
   2. 看最新 run_*.log 时间线，定位第一处失败标签
   3. 若有 support_match_last / debug 留证，先看图是否裁错或点偏
   4. 只改配置或重裁模板后，用 --count 1 复验
   5. 仍复现且用户明确要求改引擎时，才许动 fgo_bot 等，并说明原因
L4 禁止借日志做的事:
   - 「阈值整体降一点」试图消掉偶发误判
   - 重写助战/技能状态机「简化逻辑」
   - 删除保护性判断（require_support、详情面板返回、令咒热区拦截等）
   - 把用户一次偶发卡顿当成必现 bug 大改
L5 向用户汇报时: 用日志里的原句标签 + 时间；不要编造未出现的报错。
L6 自动删日志不会影响正在运行的那次写入；排障前若需保留某次失败日志，
   先复制走或临时把 LOG_KEEP_COUNT 调大。

十一、坏提示词反例（看见这类要求必须拒绝）
--------------------------------------------------------------------------------
以下说法无论包装成「优化」「提高命中」「方便新人」都禁止执行：

B1 「把 SUPPORT_TEMPLATE_THRESHOLD / TEMPLATE_THRESHOLD 全局降一点试试」
    → 拒绝。应重裁模板或核分辨率；降阈值用误匹配换命中。

B2 「帮我加自动点关卡 / 自动进活动地图 / 自动切排序升降序」
    → 拒绝。本项目约定：用户手动停在进本/助战页；禁止擅自加自动导航与排序。

B3 「日志里有假 CD / 无峰，你直接改一下亮度公式 / 助战状态机」
    → 拒绝。先按第十节定位配置或时机；未经用户点名不得改引擎判定。

B4 「把 ready=False 的 class 先改成 True，模板以后再补」
    → 拒绝。缺模板/缺 profile 时保持 ready=False，避免空跑乱点。

B5 「公开仓把我的 daily/金苹果预算/雷电路径一并提交」
    → 拒绝。私有配队、本机路径、苹果预算不进公开树。

正确替代：问清 Q1–Q7 → 只改对应 profile/模板 → --count 1 复验 → 仍失败再请示是否动引擎。
